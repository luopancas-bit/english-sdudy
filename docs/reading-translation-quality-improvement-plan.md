# 阅读翻译质量下一轮改进规范

状态：代码已实现并部署；真实翻译 provider 待人工抽样验收
优先级：P1
适用范围：`阅读学习` 的句子选择、整句翻译、翻译缓存和 Project Gutenberg 内置书解析
记录日期：2026-08-25

## 1. 问题说明

当前整句翻译服务可以正常调用本地 `llama.cpp` 模型，但实际阅读中存在以下质量问题：

1. 前端只按英文句号定位句子，网址、邮箱、缩写和小数中的点会被误判为句末。
2. 双击单词时使用单词文本的首次出现位置，段落中同一个词出现多次时可能取到错误句子。
3. Project Gutenberg EPUB 的版权头、许可证和尾注进入正文，读者打开书后会先看到并翻译非作品内容。
4. 通用 3B 模型对长句、法律条款、古典英语和网址混合句容易出现直译、生硬语序、重复或截断。
5. 翻译缓存只按用户、句子哈希和目标语言命中，没有模型版本、提示词版本、解析版本或质量状态；旧的异常结果会一直返回。
6. 当前缓存只保存哈希和译文。它符合不保存完整请求正文的隐私目标，但发生异常后无法从缓存记录单独还原原始输入。

本轮诊断中的最小复现表明，网址 `www.gutenberg.org` 会被拆成 `www.` 或 `gutenberg.`；同一模型使用当前提示词时，也能稳定复现重复和生硬翻译。因此不能只调整一个提示词，需要同时修复输入边界、书籍清理、模型调用和缓存策略。

本轮实现已进入代码并部署：前端字符偏移分句、Gutenberg 清理与解析版本、翻译质量门禁/一次重试、30 条合成基线、版本化缓存字段和幂等迁移均已加入；生产主 API、worker、内置书和缓存表迁移已验收。生产翻译 provider 已确认配置存在，但本轮未主动发起真实账号请求，需后续人工抽样确认译文自然度与缓存命中。

## 2. 改进目标

- 双击单词或选择文本时，发送给翻译接口的是用户实际所在位置的完整英文句子。
- URL、邮箱、常见缩写、小数、引号和重复单词不会破坏句子边界。
- 内置 Gutenberg 书籍默认从作品正文开始，许可证仍可通过来源信息查看，但不作为阅读章节。
- 翻译结果自然、完整，不重复、不截断，不夹带模型解释或无关续写。
- 提示词、模型或正文解析升级后，旧缓存不会覆盖新结果。
- 阅读翻译、查词和阅读进度继续不计入课程掌握率、解锁条件或正式考核。

## 3. 非目标

- 本轮不改变课程评分、单词掌握度和间隔复习规则。
- 本轮不把用户阅读正文、选择文本或完整翻译请求写入普通日志。
- 本轮不破解 DRM，也不修改受保护书籍处理边界。
- 本轮不强制更换 Qwen2.5-3B；先建立可测量的质量基线，再决定是否需要专用翻译模型。

## 4. 前端句子选择标准

### 4.1 独立模块

将当前组件内的句子截取逻辑迁移为可单测的纯函数模块：

```text
selectSentenceAt(paragraph, characterOffset) -> text
```

调用方必须传入实际点击或选区对应的字符偏移，不能再用 `indexOf(word)` 查找单词第一次出现的位置。

### 4.2 分句规则

- 优先使用 `Intl.Segmenter("en", { granularity: "sentence" })`。
- 为不支持 `Intl.Segmenter` 的浏览器提供确定性的回退实现。
- 分句前保护 URL、邮箱、小数和已登记的常见英文缩写。
- 返回文本必须经过首尾空白清理，但不得改写句中标点和大小写。
- 手动选择超过一个单词时，翻译所选内容；双击单词时，翻译该位置所属的完整句子。

### 4.3 必须覆盖的测试

- `www.gutenberg.org`、`example.co.uk/path`。
- `Mr.`、`Mrs.`、`Dr.`、`St.`、`e.g.`、`i.e.`。
- `3.14`、章节编号和带引号的句末标点。
- 同一单词在一个段落中出现两次，分别点击时得到各自所在句子。
- 段落没有句末标点时返回当前完整段落，不能返回空字符串。
- 选中跨句文本时保持用户选区，不擅自缩短为单句。

## 5. Gutenberg 正文清理标准

### 5.1 清理边界

只对明确标记为 `builtin` 或 `gutenberg` 的来源启用 Gutenberg 清理器。优先识别官方边界标记：

```text
*** START OF THE PROJECT GUTENBERG EBOOK ... ***
*** END OF THE PROJECT GUTENBERG EBOOK ... ***
```

规则：

- START 之前和 END 之后的内容不进入阅读 manifest。
- 标记不存在时，不允许凭固定页数或固定百分比大段删除正文。
- 来源、书号、许可证链接保留在书籍元数据或“查看来源”入口中。
- 用户上传的普通 EPUB/TXT 不执行 Gutenberg 专用清理。

### 5.2 解析版本

manifest 增加解析器版本，例如 `parserVersion`。清理规则变化时必须提升版本，后台任务只重建旧版本 manifest。

重新解析内置书时保留原始 EPUB。现有阅读进度优先通过正文锚点映射到新章节；无法可靠映射时保留历史记录，并明确提示用户正文结构已更新，不能静默写入错误章节。

### 5.3 必须覆盖的测试

- 有标准 START/END 标记的 Gutenberg 文本。
- 只有 START、只有 END、完全没有标记的文本。
- 正文中正常出现 `Project Gutenberg` 字样时不误删正文。
- 12 本内置样本重新解析后，第一章不包含许可证正文，最后一章不包含完整许可证附录。

## 6. 翻译服务标准

### 6.1 请求合同

后端继续只接受服务端验证后的输入，建议扩展为：

```text
text: 必填，需要翻译的英文
contextBefore/contextAfter: 可选，只帮助消歧，不得出现在最终译文
targetLanguage: 固定 zh-CN
```

提示词必须版本化，并明确要求：

- 使用自然、准确的简体中文，不逐词硬译。
- 不增加、不重复、不省略原文信息。
- URL、数字和必要的专有名词保持原样。
- 只返回译文，不返回解释、Markdown、JSON 包装或思考过程。
- 上下文只用于理解，输出只翻译 `text`。

### 6.2 生成参数

- 显式设置最大输出 token，按输入长度计算合理上限，不能无限使用服务默认值。
- 记录并检查模型返回的 `finish_reason`。
- 保持低随机性；同一输入、同一版本应得到稳定结果。
- 模型调用设置明确超时，超时后返回可理解的错误，不缓存半成品。

### 6.3 输出质量门禁

以下结果不得写入可复用缓存：

- 空结果或仅空白。
- 非短语输入却几乎原样返回英文。
- 以明显不完整的拉丁字母片段结束。
- 出现模型说明、提示词回显、代码围栏或无关续写。
- `finish_reason` 表示长度截断。
- 重复短语超过设定阈值。

质量门禁失败时允许使用更严格的修复提示重试一次。第二次仍失败则返回“翻译结果未通过质量检查，请重试”，不能把异常文本当成功结果保存。

### 6.4 模型质量基线

为 Qwen2.5-3B 建立至少 30 条不含版权正文的合成或公版测试集，覆盖：

- 日常叙述和人物对话。
- 古典英语和长从句。
- 法律/许可证句式。
- URL、数字、专有名词。
- 短语、残句和标题。

自动测试检查完整性、格式和稳定性；自然度与忠实度由人工抽样评分。若 3B 模型在基线中持续不达标，应保持 API 适配层不变，再评估专用翻译模型或更大模型，不能只通过增加提示词掩盖模型能力边界。

## 7. 缓存与数据标准

缓存身份至少包含：

```text
userId
sentenceHash
targetLanguage
provider
modelVersion
promptVersion
normalizationVersion
```

并保存不含正文的诊断字段：输入字符数、输出字符数、耗时、重试次数、`finish_reason`、质量状态和创建时间。

规则：

- 只有通过质量门禁的结果可以作为缓存命中返回。
- 提示词、模型、正文标准化或分句规则升级时，旧版本自动失效。
- 旧记录默认保留用于回滚和审计，不在迁移中直接删除；需要删除生产数据时另行取得明确授权。
- 保存到阅读笔记的译文与接口缓存分开处理，缓存失效不能删除用户主动保存的笔记。
- 数据库变更必须包含向前迁移、索引、恢复说明和旧版本兼容策略。

## 8. 隐私与可观测性

- 普通日志不记录用户完整英文正文、完整译文、Cookie、账号或书籍文件路径。
- 使用请求 ID、输入/输出长度、模型版本、提示词版本、耗时、重试次数和质量错误码定位问题。
- 需要复现正文时，只使用合成文本、公版测试句或用户明确提供的样本。
- 管理页面只展示汇总状态，不能让管理员浏览用户书籍内容或翻译历史正文。

## 9. 验收标准

以下项目全部通过才算完成：

- 点击 URL 中或 URL 附近的单词，发送的是完整句子，不是 `www.`、`gutenberg.` 等片段。
- 同一单词在段落中重复出现时，句子选择与实际点击位置一致。
- 12 本内置书的正文不再显示 Gutenberg 版权头和完整许可证尾注。
- 已知的长许可证句不出现重复、半句或英文残片。
- 异常译文不会写入缓存；相同输入修复后不会继续命中旧提示词版本结果。
- 翻译失败、模型不可用和质量门禁失败均有清晰界面提示。
- 翻译操作和缓存迁移不改变任何课程掌握率、正式成绩或复习计划。
- 单元测试、API 集成测试、`pnpm check`、桌面浏览器和 iPhone Safari 验收全部通过。
- 生产部署后验证主 API、阅读 worker、翻译模型和真实翻译请求；仅检查健康接口不足以宣布完成。

## 10. 推荐实施顺序

1. 提取并测试 `selectSentenceAt`，先修复 URL、缩写和重复单词定位。
2. 建立 Gutenberg 清理器和解析版本，使用单本样本验证后再重建 12 本内置书。
3. 抽象翻译提供方接口，加入版本化提示词、生成参数和质量门禁。
4. 扩展翻译缓存 schema 与迁移，旧缓存按版本失效但不直接删除。
5. 建立 30 条翻译质量基线和自动化回归测试。
6. 在桌面端与 iPhone Safari 完成句子选择、翻译、缓存和错误提示验收。
7. 备份数据库与阅读 manifest 后部署，验证真实请求，再决定是否清理旧缓存。

## 11. 回滚要求

- 前端分句、Gutenberg 清理器、提示词和缓存 schema 分开提交，便于独立回滚。
- 部署前备份数据库、旧 manifest 和当前镜像标签。
- 新缓存字段应允许旧应用只读启动；无法兼容时必须提供明确的镜像与数据库回滚步骤。
- 回滚解析器时恢复旧 manifest，不覆盖原始 EPUB 和用户上传文件。
- 回滚翻译服务时只切换提供方和提示词版本，不删除用户保存的译文笔记。

## 12. 完成定义

实现代码、迁移、测试、质量基线、部署说明和回滚说明全部进入同一个可审查变更；验收证据必须包含至少一个此前会失败的 URL 分句用例和一个此前会产生异常译文的长句用例。只修改提示词、只清空缓存或只确认容器健康，都不能单独视为本项完成。
